## 一、需求背景

### 1.1 市场痛点

当前职业转型市场存在以下问题：

| 痛点 | 现状 | 影响 |
|------|------|------|
| 信息不对称 | 转行者不清楚目标岗位的真实要求 | 盲目转行，成功率低 |
| 主观判断 | 职业建议多基于经验和直觉 | 缺乏数据支撑，可信度低 |
| 路径模糊 | 不知道需要补充哪些技能 | 学习投入产出比不清晰 |
| 案例稀缺 | 成功转行案例难以规模化获取 | 无法借鉴他人经验 |

### 1.2 数据资源

现有招聘数据资源：

```
智联招聘数据库（2016-2025）
├── 数据格式：Stata .dta
├── 数据规模：约 50GB+
├── 时间跨度：2016-2025年
├── 覆盖范围：全国主要城市、各行业
└── 核心字段：岗位名称、任职要求、薪资、学历、经验等
```

### 1.3 项目价值

利用海量招聘数据，构建**数据驱动的转行可行性分析系统**，为职业转型者提供：
- 量化的岗位匹配度评估
- 可视化的技能缺口分析
- 个性化的转行路径推荐

```python
import pandas as pd
import duckdb
from pathlib import Path

def convert_dta_to_parquet(input_file: str, output_dir: str, chunk_size: int = 100_000):
    """分块读取 .dta，转存为 Parquet"""
    output_path = Path(output_dir)
    output_path.mkdir(exist_ok=True)

    reader = pd.read_stata(input_file, chunksize=chunk_size, convert_categoricals=False)

    for i, chunk in enumerate(reader):
        # 数据清洗
        chunk = clean_data(chunk)
        # 写入 Parquet
        chunk.to_parquet(output_path / f'part_{i:04d}.parquet', index=False)
        print(f'已处理: {(i+1) * chunk_size:,} 行')

def query_with_duckdb(parquet_dir: str, sql: str) -> pd.DataFrame:
    """使用 DuckDB 查询 Parquet 文件"""
    con = duckdb.connect()
    con.execute("SET memory_limit = '12GB'")
    con.execute("SET temp_directory = 'E:/duckdb_temp'")

    # 直接查询所有 Parquet 文件
    result = con.execute(f"""
        SELECT * FROM '{parquet_dir}/*.parquet'
        WHERE {sql}
    """).df()

    return result
```

### 3.4 匹配度算法

#### 3.4.1 技能匹配度计算

```python
def calculate_match_score(person_skills: dict, job_requirements: list[dict]) -> float:
    """
    计算人群与岗位的技能匹配度

    person_skills: {"沟通能力": 0.95, "耐心": 0.92, ...}  # 人群技能及掌握程度
    job_requirements: [{"skill": "沟通能力", "weight": 1.0}, ...]  # 岗位要求
    """
    total_weight = 0
    matched_score = 0

    for req in job_requirements:
        skill = req["skill"]
        weight = req["weight"]  # 必备=1.0, 优先=0.6, 加分=0.3

        total_weight += weight
        if skill in person_skills:
            matched_score += weight * person_skills[skill]

    return matched_score / total_weight if total_weight > 0 else 0
```

#### 3.4.2 转行可行性综合评估

```python
def evaluate_transition_feasibility(
    skill_match: float,      # 技能匹配度 0-1
    barrier_score: float,    # 门槛友好度 0-1
    skill_gap: int,          # 技能缺口数量
    gap_cost: float          # 缺口填补成本（月）
) -> float:
    """综合转行可行性评分"""

    feasibility = (
        0.40 * skill_match +
        0.30 * barrier_score +
        0.20 * (1 - min(skill_gap / 10, 1)) +
        0.10 * (1 - min(gap_cost / 12, 1))
    )

    return feasibility
```

### 3.5 知识图谱设计

#### 3.5.1 节点类型

```
[岗位] - 属性：名称、薪资范围、经验要求、学历要求
[技能] - 属性：名称、类别、学习成本、市场需求度
[能力] - 属性：名称、类型（软技能/硬技能）
[证书] - 属性：名称、考取难度
[人群] - 属性：名称、典型技能集
```

#### 3.5.2 关系类型

```
岗位 --[需要]--> 技能 (权重: 必备/优先/加分)
技能 --[依赖]--> 技能 (前置技能关系)
技能 --[可替代]--> 技能
人群 --[具备]--> 技能 (掌握程度: 0-1)
岗位 --[晋升至]--> 岗位
```

#### 3.5.3 核心查询示例

```cypher
// 查询：幼师转新媒体运营需要补充哪些技能？
MATCH (p:人群 {名称:"幼师"})-[r1:具备]->(s1:技能)
MATCH (j:岗位 {名称:"新媒体运营"})-[r2:需要]->(s2:技能)
WHERE NOT EXISTS((p)-[:具备]->(s2))
RETURN s2.名称 AS 缺口技能,
       r2.权重 AS 重要性,
       s2.学习成本 AS 学习周期
ORDER BY r2.权重 DESC
```
